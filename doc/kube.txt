1. Introduction                                         *kube.nvim* *kube*

kube.nvim shows Kubernetes resources in buffers: lists, `kubectl describe`,
YAML, logs, events, decoded secrets and Helm releases. Delete a line and |:w|
to delete a resource, edit the YAML and |:w| to apply it.

Requirements: Neovim >= 0.11 and `kubectl` in $PATH. `helm` in $PATH for Helm
releases, see |kube-helm|.

|setup()| is optional, the |:Kube| command and the `kube://` buffers work
without it.

==============================================================================
2. Commands                                                    *kube-commands*

                                                                       *:Kube*
:Kube get {kind} [namespace={ns}] [selector={labels}]
    Open the list of {kind}, in all namespaces unless {ns} is given.
    Example: `:Kube get pods selector=app=web,tier=frontend`

:Kube delete {kind} {name} [namespace={ns}]
    Delete a resource after confirming. Without {ns}, in the `default`
    namespace, whose resource names {name} completes.

:Kube context [{context}]
    Switch the context used by new buffers, only in kube.nvim: the kubeconfig
    is not changed. Without {context}, select one.

:Kube apply                                                      *:Kube-apply*
:Kube! apply
    Apply the current buffer as a manifest to the current context, after
    showing `kubectl diff` and confirming. With ! there is no confirmation.

:Kube diff                                                        *:Kube-diff*
    Show `kubectl diff` of the current buffer as a manifest.

:Kube portforwards                                        *:Kube-portforwards*
    List all port forwards, of all contexts. Delete a line and |:w| to stop
    the port forward.

3. Buffers                                                      *kube-buffers*

Every view is a buffer named: >
    kube://[context/{context}/][namespaces/{ns}/]{kind}[/{name}[/{sub}]][?{params}]
<
Examples: >
    :e kube://                               " the resource types, see below
    :e kube://deployments                    " all namespaces
    :e kube://namespaces/staging/deployments " the staging namespace
    :e kube://context/production/pods        " the production context
    :e kube://helm                           " Helm releases, see |kube-helm|
<
A name without `context/{context}/` is an alias for the current context:
editing it edits the buffer with the context in its name, so the buffer keeps
operating on that cluster after switching contexts with |:Kube| context. The
alias buffer is wiped, it is never the |alternate-file| nor in the |jumplist|.
Likewise `ctx` is short for `context`, `ns` for `namespaces` (and `helm` for
`helm-releases`, see |kube-helm|): `:e kube://ns/staging/pods` edits
`kube://context/{context}/namespaces/staging/pods`, and a name without {kind}
edits `api-resources`: the resource types of the cluster (`kubectl
api-resources`). <CR> or |CTRL-]| on one lists it, in {ns} for namespaced
types of `kube://ns/{ns}/api-resources`.
Contexts with `/` or `:` are percent-encoded.

Every jump (<CR>, |gd|, |CTRL-]|, `-`, `gl`, ...) is an |:edit| of the target
buffer in the current window, so kube buffers behave like file buffers:
|CTRL-O|, |CTRL-^|, |CTRL-T| go back; |'hidden'| and |'bufhidden'| decide
whether a buffer you leave is hidden or unloaded; modified buffers are
protected as usual (|E37|, |E89|). An unloaded buffer stops its kubectl jobs
(e.g. following logs) and loads again when edited, keeping its state (e.g.
watching); |:bdelete| and |:bwipeout| discard the state. |:e| reloads.

Kinds are group qualified (e.g. `deployment.apps`) so kubectl never picks a
same-named kind of another API group.

Views of a resource ({sub} and {params}):
    `?output=yaml`          The YAML, editable, see |kube-editing|
    (none)                `kubectl describe`
    `/containers`           The containers of a pod
    `/logs`                 Logs, params: `container`, `follow`, `previous`,
                          `all-containers`, `since` (e.g. `1h`), `tail`
    `/portforward`          The port forwards of the resource
    `/history`              `kubectl rollout history`
    `/data`                 The decoded data of a secret, see |kube-secrets|
    `/exec`                 A shell in the resource (|terminal|), param: `container`
    `/debug`                A shell in an ephemeral container of a pod
                          (`kubectl debug`), params: `image`, `target`
Lists take kubectl flags as params, e.g. `?selector=app=web` or
`?field-selector=involvedObject.name=web`.

Lists of pods and nodes have CPU and MEMORY columns (`kubectl top`) when the
cluster has the metrics API, e.g. with metrics-server. Statuses are shown as
kubectl does: `CrashLoopBackOff`, `Init:0/1`, `NotReady,SchedulingDisabled`, ...
Followed logs keep the cursor at the end when it is on the last line.
Logs can be edited to make them readable, e.g. `:%!jq` or `:%!jq .message -r`
for JSON logs. There is nothing to write back: |:w| fails and keeps the edits,
`:w {file}` saves them, |:e| reloads.

4. Keymaps                                                      *kube-keymaps*

Keymaps follow Neovim's conventions: LSP's |gd|, |gD|, |K|, |CTRL-]| and the
built-in directory browser's <CR>, `-` and `R`. Press `g?` for the help.

    <CR>    Drill down: a pod's containers, a deployment's pods, a secret's
            decoded data, ...
    gd      Go to what the cell under the cursor refers to, see |kube-jump|
    gD      Go to the owner: pod -> replica set -> deployment, job -> cron job
    K       Describe the resource under the cursor, explain a resource type
            (`kubectl explain`) in `kube://` (LSP hover)
    -       Parent: resource -> list in its namespace -> all namespaces ->
            namespaces -> resource types
    R       Reload, the cursor stays on the same resource
    gw      Toggle watching: reload the list every `refresh_interval`
    gl gL   Show / follow logs, <C-c> stops following
    gf      Forward ports
    gF      Show port forwards
    gi      Set image
    gs      Shell (`kubectl exec`)
    g?      Help

                                                                   *kube-jump*
|CTRL-]| (and |gd|) jump to what the cell under the cursor refers to:
    NAMESPACE       the same list in that namespace
    NODE            the node
    OBJECT (events) the involved object
    a namespace row the pods in it
    a resource type the list of that type
    a Helm release  its values, a revision its manifest, see |kube-helm|
    anything else   the resource's YAML
|CTRL-T| jumps back and |CTRL-W_]| opens the jump in a split, as with tags.

Built-in keys that also work: |]d| / |[d| to the next / previous unhealthy
resource, |CTRL-W_d| shows why, |gx| opens a port forward URL.

5. Language server                                                  *kube-lsp*

kube.nvim attaches an in-process language server named "kube" to its buffers,
so LSP keymaps and pickers work on them:
    hover               describe, explain a resource type, `helm status` of
                        a release (|K|)
    definition          |kube-jump|
    declaration         the owner of the resource (|gD|)
    references          the pods using a config map, secret, persistent
                        volume claim, service account or node (|grr|), as
                        rows of `kube://.../pods?using={kind}/{name}`
    document symbols    the resources of the list (|gO|)
    selection ranges    the cell, the row, the list: |an| / |in| (Neovim 0.12+)
                        select them, e.g. `can` changes an editable cell
    code lenses         Show logs, Follow logs and Exec above each container
                        of the YAML of a pod or a workload, run with |grx|
                        (Neovim 0.12+) or |vim.lsp.codelens.run()|; shown
                        with |vim.lsp.codelens.enable()|
    code actions        every operation on the resource under the cursor
                        (|gra|), or on all resources of a visual selection:

    Open, Describe, Go to YAML, Show events, Show logs, Follow logs, Show logs
    of all containers, Show logs of the previous instance, Show logs since…,
    Exec, Debug (ephemeral container), Forward port, Show port forwards, Set
    image, Scale…, Restart, Undo rollout, Rollout history, Trigger now (cron
    jobs), Decode secret, Cordon, Uncordon, Drain, Delete

    Resource types (`kube://`): List, List in all namespaces, Show events.
    Port forwards: Open in browser, Go to the resource, Stop.
    Helm releases and their revisions: see |kube-helm|.

Operations changing the cluster ask for confirmation, naming the context.

6. Editing                                                      *kube-editing*

Lists: delete lines and |:w| to delete those resources (uninstall those Helm
releases, see |kube-helm|), after confirming. The
deleted lines stay visible, as virtual lines, until written or undone. Deleted
lines and edited cells are confirmed together.

Edit cells and |:w| to apply them, after confirming all changes; |:w!|
without confirming. Editable cells are highlighted with `KubeEditable`:
    DESIRED     deployments, statefulsets, replicasets: scale
    IMAGE       containers of a pod: set the image
    SUSPENDED   cron jobs: `true` or `false`
|:w| refuses edits of the other cells and keeps them, to fix or undo.

Watched lists (`gw`) highlight the lines a reload changed for a moment.

YAML (`gd`): |:w| shows `kubectl diff` and applies after confirming. |:w!|
applies without confirming.

                                                                *kube-secrets*
Decoded secrets (<CR> on a secret): one `key: "value"` per line, values in
JSON string syntax (`\n`, `\"`, ...). Values that are not UTF-8 are shown as
`key: !!binary "<base64>"`. |:w| patches the secret after confirming the added,
changed and removed keys; |:w!| without confirming.

7. Helm                                                            *kube-helm*

Helm releases are listed with `helm`, in the context and namespace of the
buffer, like the other lists: >
    :e kube://helm-releases                  " all namespaces
    :e kube://ns/staging/helm                " short for `helm-releases`
    :Kube get helm namespace=staging
<
The list (`helm list`) shows releases of all statuses: failed releases
are errors and pending ones warnings, see |]d|.

Views of a release, `kube://.../namespaces/{ns}/helm-releases/{name}[/{sub}]`:
    (none)                `helm status`, also the hover (|K|) of a release
    `/manifest`             What it deployed (<CR>), param: `revision`
    `/values`               The user supplied values (|gd|, |CTRL-]|), params:
                          `all` (the computed values), `revision`
    `/notes`                The notes of the chart
    `/history`              The revisions, <CR> on one shows its manifest

Values are read-only: a release does not record where its chart comes from,
upgrade it with `helm upgrade`.

Code actions (|gra|) of a release: Show manifest, Show values, Show all
values, Show notes, Show status, Show history, Rollback to the previous
revision, Uninstall (also of the releases of a visual selection). Of a revision of the
history: Rollback to revision {n}, Show manifest / values of revision {n}.

Delete lines and |:w| to uninstall those releases, after confirming, as with
resources, see |kube-editing|.

8. Configuration                                                 *kube-config*

Defaults: >lua
    require("kube").setup({
      keymaps = {
        drill_down = "<cr>", show_yaml = "gd", owner = "gD", describe = "K",
        parent = "-",
        refresh = "R", watch = "gw", show_logs = "gl", follow_logs = "gL",
        port_forward = "gF", forward_port = "gf", set_image = "gi",
        exec = "gs", help = "g?",
      },
      -- How often watched lists (gw) reload, in ms, false to disable watching
      refresh_interval = 10000,
      -- kubectl --request-timeout, except for streams (logs -f, port-forward)
      request_timeout = "30s",
      logs = {
        tail = 1000,       -- lines to fetch, -1 for all
        max_lines = 10000, -- lines kept while following, -1 for all
      },
      -- Overrides, by default linked to your colorscheme's groups:
      -- KubeBody (Normal), KubePending (DiagnosticWarn),
      -- KubeRunning (Normal), KubeFailed (DiagnosticError),
      -- KubeSucceeded, KubeUnknown (Comment), KubeHeader (Title),
      -- KubeDeleted (DiffDelete), KubeChanged (DiffChange),
      -- KubeEditable (Identifier)
      -- e.g. { KubeHeader = { fg = "#df8e1d", bold = true } }
      highlights = {},
    })
<

9. Health                                                        *kube-health*

`:checkhealth kube` checks the Neovim version, kubectl, helm (optional), the
current context and whether its cluster is reachable.
